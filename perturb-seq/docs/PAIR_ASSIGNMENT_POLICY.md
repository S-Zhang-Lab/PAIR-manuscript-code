# PAIR Assignment Policy

## Default policy

The default PAIR assignment used for downstream analysis is the **legacy
max-UMI call**:

- `assigned_tag` = tag with the highest PAIR UMI in that cell
- no minimum UMI threshold is required for the default call
- no ambiguity filter is applied to the default call

## Rationale

This experiment differs from a conventional pooled mixed-infection
assignment problem. Each PAIR line was generated by **separate
transfection and stable selection**, so each cell should carry **one known
PAIR construct before pooling**. After those individually generated cell
lines were mixed for perturb-seq, low PAIR UMI capture is interpreted
primarily as **sparse detection of a true single-construct identity**
rather than de novo assignment from a mixed library.

Under that design:

- a single detected PAIR tag is biologically plausible,
- low UMI mostly reflects capture sparsity,
- aggressive thresholding is more likely to create false negatives than
  to prevent many false positives.

## Diagnostic metadata retained

Even though `assigned_tag` uses the permissive legacy call, PAIR
diagnostic fields are still computed in `code/organize_data.R`:

- `assigned_tag_legacy`
- `assigned_tag_confident`
- `top_tag`
- `top_umi`
- `second_tag`
- `second_umi`
- `assignment_margin`
- `second_to_top_ratio`
- `total_pair_umi`
- `assignment_status`

These fields are intended for **QC and sensitivity analysis**, not to
replace the default downstream assignment unless explicitly requested.

## Recommended manuscript language

Suggested wording:

> Each PAIR cell line was generated separately by transfection and stable
> selection prior to pooling, so each cell was expected to contain a
> single predefined PAIR construct. We therefore used the detected
> highest-UMI PAIR tag as the default construct assignment and treated low
> UMI capture primarily as sparse detection rather than as evidence of
> construct ambiguity. Assignment-margin and multi-tag diagnostics are
> reported as sensitivity/QC metrics.
